# Gutenkern — алгоритм генерації пар

Спільне джерело правди для Swift- і C#-реалізацій. Поведінку фіксують тести з `fixtures.json`.

## Парсер

Вхід — один рядок (або кілька, з переносами). На виході — список токенів:

- **character** — один графемний кластер (звичайна літера, включно з кирилицею, `Þ`, `Æ`)
- **name** — ім’я гліфа без слеша (`elcyr.alt`)

Правила, зліва направо:

1. Пробіл, таб, перенос рядка — роздільник, пропускається.
2. `/` починає ім’я. Ім’я триває до наступного `/`, пробільного символу або кінця рядка. Порожнє ім’я (`//` або зайвий `/` в кінці) ігнорується.
3. Будь-який інший символ — окремий character-токен.

Порядок зберігається. Дублікати не прибираються.

Приклади:

- `g/elcyr.alt` → `g`, `elcyr.alt`
- `/Zhecyr.alt/zhecyr.alt` → `Zhecyr.alt`, `zhecyr.alt`
- `  н о\nг  ` → `н`, `о`, `г`

## Пари

Декартовий добуток: для кожного гліфа A з поля 1 і кожного B з поля 2.

- **Прості:** послідовність `[A, B]`
- **Дзеркальні:** послідовність `[A, B, A]` (ABA)

Якщо хоча б одне поле порожнє після розбору — результат порожній рядок. Інакше кожна пара — окремий рядок. Пари одного лівого гліфа утворюють групу; між групами стоїть порожній рядок (`\n\n`). Після останньої групи зайвого переносу немає.

## Формати

Токени збираються в рядок так:

**FontLab.** Усі токени з’єднані слешем. Символ як є, ім’я без додаткового префікса. `н` + `elcyr.alt` + `н` → `н/elcyr.alt/н`.

**Glyphs.** `/` починає ім’я гліфа, звичайні літери пишуться як Unicode:

- character → сам символ
- name → `/` + ім’я
- якщо попередній токен був name, а поточний — character, перед символом ставиться пробіл, щоб ім’я не «з’їло» наступну літеру

Приклади Glyphs: `нон`, `н/elcyr.alt н`, `/Zhecyr.alt/zhecyr.alt`.
